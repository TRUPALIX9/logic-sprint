Logic Sprint · Game 05 · Plan

Angle Sense

An angle appears. You call how many degrees it is. Close enough and you keep going. Pick Easy, Medium or Hard. Every stage brings a new kind of angle and a slightly tighter window, sized from how accurately people really judge angles. Calls within ±3° earn a Sharp bonus, within 1° a Bullseye. A miss cracks one of your 3 strikes; the third ends the run.

01 · What you measure

Six angle scenes

Same question every time ("how many degrees?"), asked through different everyday shapes so the run never feels like one drill. Each scene is a painter that returns a vertex, a starting arm and the answer, so the reveal overlay works the same for all of them.

02 · Easy, Medium, Hard

Three ways to see an angle

Each difficulty changes what the angle hangs on, not only how strict the check is. Easy keeps one arm fixed on the x-axis. Medium uses things with a built-in reference (a clock's 12, a pie's top, north on a compass). Hard spins everything at random and makes up for it with a wider window. Every window comes from a simple model of human error, so the game stays fair for normal people.

Easy · fixed base

±8° → ±5°

One arm always lies flat along the x-axis, pointing right. You only judge how far the other arm opens. Lines first, then two crossing lines where one is flat. Draw mode joins at Q26, still from the flat arm. No timer.

Medium · fixed reference

±8° → ±5°

Clock hands, pie slices that start at 12 o'clock, compass bearings from north. The reference never moves, but the other side does. A timer from Q13; Draw mode ("set the hand to 135°") from Q21.

Every 10th question is a phone-compass round: turn your real phone until you face the bearing shown (say, SE · 135°), hold it for a second. Wider ±12° window and no timer, so it's a breather between the timed stretches.

Hard · anything goes

±9° → ±6°

Random rotation on every question: lines, crossings, pie slices, triangles, then Draw, big reflex angles and trick drawings. Random angles are much harder to read, so the window stays a degree wider than Medium's. It still tightens and the timer starts at 6 s on question 1, so it never gets easy.

How often a typical player lands inside the window

A typical adult's guess on two plain lines is off by about 5° (one standard deviation). Fixed-base angles are easier (about 4°), randomly rotated ones harder (6–9°). Hit chance on plain lines, and of ten hits in a row:

A fixed ±3° window would end almost every run inside ten questions. That's why ±3° is a Sharp bonus (+5) rather than the pass mark, and within 1° is a Bullseye (+10).

3 strikes: windows of ±8° down to ±5° feel precise, but with one-miss-ends-it a typical Medium player would be out by question 5. Angle Sense alone gives three strikes: a miss cracks one marker, the third crack ends the run, and a revive brings the run back as in every game. A miss here is "a bit off", not a wrong answer.

In the app

GameId.hasDifficulty includes angleSense, so the game sheet shows Easy / Medium / Hard like Memory Lane and Quick Math. detail(difficulty) returns the one-line summaries above, and each difficulty gets its own leaderboard board.

Phone-compass round: read the heading with a compass plugin (for example flutter_compass, or sensors_plus magnetometer). Show a live arrow and the target, and count it as a hit once the heading stays within ±12° for one second. With no compass (simulator, some tablets) or before calibration, the round falls back to dragging the needle on screen. No location permission is needed for heading.

The window shown during play is exactly the one that's checked.

03 · Screen design

Three moments of a question

Layout mirrors Guess Color: game bar, rule tabs, square card, input underneath. Gold is this game's accent the way violet is Guess Color's. No live degree readout ever appears on the card in DRAW, or the game becomes a reading test.

Input: the degree tape

A horizontal tape like a measuring tape under a fixed needle. Flick for big moves, nudge ±1 for the last bit, Lock to submit. It is thumb-sized, never covers the angle, and gives continuous values so the ±3° window means something. The readout above it shows your number in big mono digits.

Rejected: number keypad (slow, three taps plus enter, feels like Quick Math). 4-choice buttons (turns a ±3° skill into guessing between 4 options; fine as an onboarding hint only).

Feedback: the reveal

After Lock the true arm sweeps in gold over 250 ms, your guess shows as a dashed teal arm, and a chip says the error: +2°. Inside the window = HIT; within 1° = BULLSEYE with a stronger haptic; outside = MISS and the run goes down (revive offer if score ≥ 50).

Haptics and sounds reuse RoundFeedback.correct() / wrong(); bullseye adds a second light tap.

05 · Playbook

From plan to store

Order matters in two places: the backend constraint ships before the app, and tuning happens before store screenshots.

Lock the design

0.5 day
  • Agree on name, accent, the six scenes and the stage table on this page.
  • Draw AngleSense.dc.html wireframe: READ, DRAW, reveal, run over.
  • Decide the open questions at the bottom of this page.

Engine first, with tests

1–1.5 days
  • Write AngleSenseEngine and its tests before any UI. Seeded Random so tests pin exact questions.
  • Error is the shortest way round the circle: min(|g−a|, 360−|g−a|), so 359 vs 1 is 2°, not 358°.
  • Run flutter test green.

Painters and tape

2 days
  • Build each scene painter against a debug screen that cycles seeds.
  • Tape: fling, ±1 nudge, haptic tick every 5°, VoiceOver/TalkBack label "Your guess, 172 degrees".
  • Test on the smallest phone (SE) and on iPad inside tablet_frame.

Wire into the app

1 day
  • Add the enum value, route, home grid change, ranks short title.
  • Pause, background, revive and result screen come free from RoundEngine; check the countdown freezes on pause.

Backend before release

0.5 day
Deploy order: run the Supabase migration that allows 'angleSense' before the app build reaches anyone. An app that submits a game name the check constraint rejects will lose those scores silently. Old app versions are unaffected.

Playtest and tune

2–3 days
  • Five or more people, ten runs each. Log every guess and error.
  • Targets: median run reaches Q15–20; fewer than 1 in 5 runs die in Basics; ±3° at Q41+ hit about 40% of the time.
  • Tune windows and timers only in the engine's constants.

Store and release

1 day
  • Screenshot 10_angle_sense for App Store, 6.5", iPad and Play; update the home screenshot (now 5 games).
  • Release notes and listing line: "New game: Angle Sense. How close can you call it?"
  • Ship as 1.1.0: a new game is a minor version, not a patch.
06 · Decide before building

Open questions

Name"Angle Sense": its own name, so it doesn't read as a Guess Color variant. Other options: Sharp Eye, Right Angle.
±3° goalKept as the Sharp bonus (+5) rather than the pass mark. The model shows a fixed ±3° window ends almost every run in under ten questions, even for good players.
3 strikesDecided: tight windows (±8° → ±5°) with three strikes per run. Angle Sense is the only game where one miss doesn't end the run, because a miss here is "a bit off", not a wrong answer. Revives work on top.
DRAW modeAdds the most variety but is the most work (drag-to-aim on the card). Can ship READ-only first and add DRAW in 1.1.1.
Clock scenePlayers who know clock maths can compute it instead of eyeballing. Keep it (it's fun and fair) or limit to odd minutes.
Home gridFull-width fifth card with a NEW tag (recommended), or switch the grid to a scrolling list now to make room for more games.
07 · What could come next

More games in the same mould

Every idea keeps the Logic Sprint rules: one screen, endless run, one mistake ends it, difficulty that ramps up as you go, a single skill tag. Ordered by how well they fit and how cheaply they build on what Angle Sense adds.
